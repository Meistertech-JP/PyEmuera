# Post-Beta 1 古ハングル／Jamo照合：第2段階の技術記録

この文書は portable 照合の開発候補について、有限の入力で得た観測と残る制限を説明する。Windows の照合仕様全体や、次の公開版の承認を意味するものではない。以下の比較は原則として文字列の**正逆を別々の方向**として数える。

## 実装と識別

| 識別子 | 内容 | `pyemuera/collation_portable.py` の SHA-256 |
| --- | --- | --- |
| B0 | 公開済み 3.0.0 Beta 1 相当 | `722685b552893c526f12fc37caa9d2660ba27f25060f46dc37c3249d33ec15ca` |
| C1 | 前段階の限定修正、commit `d91b13a0a84a2789e183430dc33bdc2a002a9c70` | `86492ebbca338c6bd8a522a28b1560e855df4c9814c6d1d8ea482c94ad439a0d` |
| C2 | 第2段階の性能上の変更、commit `d1ba27f29d3bb5fb6f71ec644217bb656e2897fe` | `108cc50f5b96b8db769bf2b159f7f0013229bb36a9ffef56a1a54ecb43ee336f` |

C1 の `_decisive_prefix_jamo_sign` は、異なる単一 class-6 接頭辞の直後に Jamo があり、重みやクラスタ形状が限定条件を満たす場合に、後続 Jamo の差で比較を決定する。条件外は `None` を返し従来経路へ戻る。等値 `0` は未判定を表さない。C2 は通常の `str` 同士でサブクラスの特殊メソッド検査ループを省き、特殊な文字列アクセスを持つ型の従来の判定は維持する変更である。残存不一致に対する新たな照合規則は追加していない。

## 保存済み比較とソートの観測

Windows 10 build 19045.7807、.NET Framework 4.8.1 release 533509、`ja-JP`、`CompareOptions.None`、NLS `0x60305` の記録に基づく。各候補を別プロセスで固定 pyz から読み、保存された Framework の比較符号と照合した。母集団には重複があり、足し合わせて全体互換率とはしない。

| `r49/prefix_alignment` の36,864方向 | B0 | C1 | C2 |
| --- | ---: | ---: | ---: |
| 一致 | 35,672 | 35,768 | 35,768 |
| 不一致 | 1,192 | 1,096 | 1,096 |

前段階の改善96方向は入力と期待符号を行単位で照合し、C2でも96方向すべてを維持した。この基準集合では C1→C2 の追加改善と退行は0。現代 Leading Jamo 側の18,432方向は各候補で全て一致した。その他の保存済み比較集合と選別済み開発・反例の範囲でも、C1一致→C2不一致、B0一致→C2不一致は0だった。たとえば decisive Jamo 開発用22方向は B0 で8、C1/C2で22が一致したが、選別された例であり代表的な一致率ではない。

C2の残存1,096方向は、portable側の `_separator_jamo_sign` が結果を返した方向であり、Windows内部の同名の分岐を意味しない。B0の同分岐における保存済み不一致集合と、入力・期待符号・方向を行単位で照合した。これは全Jamo入力の性質ではない。

同じ固定候補のソート再生では、Framework `List.Sort`／`ARRAYMSORT` 相当61件と `Array.Sort` 188件の記録された比較呼出し列がそれぞれ全件一致し、正常例の順列も一致した。例外は有無のみの比較で、例外型や部分配列の一致を意味しない。本家 `ARRAYSORT` 6件は最終値のみ一致し、呼出し列の原票はない。既存VMテストは関連配列・RESULT・RNGを検査した範囲の確認である。

4つの開発・反例 fixture の80方向を同環境のFrameworkで再測定し、`String.CompareTo`、`CompareInfo.Compare`、長さを明示した `CompareStringEx` の符号が保存期待値と一致した。他の全原票を再採取したという意味ではない。直接比較と単独の `GetSortKey` の大小は別の観測である。

固定C2 pyzの独立した全テスト記録は3,366件中3,359 PASS、7 SKIP、FAIL／ERROR 0。Linux実測はこの記録の対象外である。過去に評価済みの3,000方向対照はB0・C1・C2で再生し全方向一致した。C1・C2は全方向で限定判定から従来経路へ戻ったため、限定規則が決定する入力の実証ではない。

## 状態遷移と未解明条件

残存例2方向を基に、一度に1条件を変えた18ケースの正逆36方向をFrameworkで測定したところ、C1は12方向で一致、24方向で不一致だった。これは代表例の制御実験であり、残存集合の分布推定ではない。NULを DEL に変える操作や片側末尾の削除は、一部の例で直接比較の符号を変えた。共通末尾・共通接頭辞を加えたこの2基底では符号が保持されたが、一般則は導けない。

このうち2方向の専用子プロセス追跡では、先行sampleのカテゴリに基づく32ビット比較の迂回、mapperの値、cursor位置と終端結果を観測した。観測フィールドへの書込みと符号変化の併存は、因果関係の証明ではない。別の有限トレースでは sentinel 時の読込み、それ以外の再利用、mapper戻り1・2に伴う追加cursor移動も観測されたが、全ての更新・無効化条件は未確定である。

入力だけから状態を予測する限定モデルは、開発Oracle 200,532方向中1,350方向に符号を返したが、残存不一致は全て `UNKNOWN`、改善0だった。nativeで観測した中間状態を与えた後半分岐の検算やトレース再生は、独立した比較器の成功に数えない。保留結果の優先順位、bufferの全更新条件、逆方向や未追跡ケースの状態、入力から各状態を予測する条件は未解明である。

## 性能測定の範囲

Windows、CPython 3.12.10、同一マシン・入力で、B0/C1/C2を独立プロセスに分け、実行順を循環させた9ブロックの比較処理マイクロベンチを行った。各カテゴリ128ペア、ウォームアップ後の初出と反復を別に測定した。反復は比較経路のキーLRUヒットを意味しない。

中央値の例では、日本語初出は B0/C1/C2 がそれぞれ56.96/56.30/57.12 µs、境界例の初出は49.30/57.07/50.89 µsだった。大きな外れ値があり、CPU負荷も完全には隔離していないため、微小な差やC2による速度改善は確定できない。集計符号の一致は各入力の非退行の証明ではなく、測定値はアプリ全体の速度を示さない。

## 公開ソースで再実行する

以下はこの開発ソースのリポジトリルートで実行する。Python 3.10以上とGitが必要。`--out` は**まだ存在しない**出力ディレクトリを指定する。基準fixtureは `tests/fixtures/r49/prefix_alignment.json.gz`、SHA-256 は `4d6b753a4c511480931862550e2e86f9e4d1476f3f7bf7424974f574dee18672`。

```powershell
python -B tools/replay_post_b1_baseline.py --repo . --out <新しい出力ディレクトリ>
python -B -m unittest discover -s tests -p 'test_framework_decisive_jamo_development.py' -v
```

前者は現在の**ソース**で保存済みFramework期待値を再生し、`summary.json` と不一致の診断 `mismatches.json` を生成する。既知不一致の存在だけでは失敗終了しない。C2の固定状態なら36,864方向中35,768一致、1,096不一致が目安となる。異なる実装では結果も変わり得る。再生はFrameworkの再測定やpyzの検証ではなく、96方向の集合維持を単独で証明するものでもない。

Windows上で .NET Framework compiler が利用できる場合、公開された4つの小規模開発fixture、計80方向の直接比較を再測定できる。compilerは対象環境の Framework 4.x `csc.exe` を指定する。

```powershell
python -B tools/verify_post_b1_framework_fixtures.py --csc <Frameworkのcsc.exe> --output <新しい出力ディレクトリ>
```

出力のプロファイルと3 APIの符号を確認する。異なるNLSプロファイルの結果を元の観測へ無条件に混ぜない。詳細な入力生成の方法とfixtureの選別条件は [Post-Beta 1 Framework 比較データの生成](../tools/POST_B1_ORACLE_ja.md) を参照。第2段階の性能ベンチ、状態制御・native追跡、全候補の行単位照合は上記コマンドだけでは再現されない。

この文書はソースリポジトリ向けで、現行の `tools/build_pyz.py` の組込み文書一覧や `packaging/public/selection.json` の配布ソース選択には含まれない。配布ZIPへ含めるには別途選択ルールの変更が必要である。
